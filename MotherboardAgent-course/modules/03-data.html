The Data Warehouse

How nine scraped fields become a structured JSON file — the shared language between scraper and dashboard.

JSON: the sticky note that everyone can read

After the scraper visits hundreds of Newegg pages, it needs to save the data somewhere that the dashboard generator can read later. It uses a format called JSON — a text file with a very specific structure that every programming language can read and write.

Think of JSON like a well-organized filing cabinet where every drawer is clearly labeled, every folder has a consistent layout, and any coworker — regardless of their background — can find exactly what they need.

{ }

Object / Dictionary

A set of labeled values. Like a named box: "brand": "ASRock". Keys are always strings in quotes.

[ ]

Array / List

An ordered collection of items. Like a numbered row of shelves: ["ASRock", "ASUS", "MSI"]

42

Number / String

Raw values. Numbers need no quotes: 4.6. Text needs quotes: "X870E".

Inside motherboard_reviews.json

Here's what one product looks like after the scraper is done with it. This is the exact format stored in the file:

JSON STRUCTURE 
{
  "source": "Newegg",
  "retrieved_date": "2026-04-14",
  "brands": {
    "ASRock": {
      "products": [
        {
          "name": "X870E Nova WiFi",
          "socket": "AM5",
          "chipset": "X870E",
          "form_factor": "ATX",
          "rating": 4.6,
          "review_count": 282,
          "price_usd": 259.99,
          "category": "AMD"
        }
      ]
    }
  }
}
PLAIN ENGLISH

The outer object is the whole file. Everything lives inside it.

"source" tells us this data came from Newegg — useful if you ever mix data from multiple sources.

"retrieved_date" is a timestamp — so the dashboard can show "data as of April 14."

"brands" contains one entry per brand scraped. Each brand is its own labeled box.

Inside each brand is a list called "products" — an array of product objects.

Each product is its own object with these labeled fields.

"name" is the product model (brand prefix stripped off).

"socket" — which CPU generation this board supports. Extracted from the product name.

"chipset" — the feature tier of the board. Also extracted from the name.

"form_factor" — the physical size of the board.

"rating" — average star rating (1.0–5.0).

"review_count" — how many reviews have been written. More reviews = more reliable rating.

"price_usd" — price in US dollars, rounded to two decimal places.

"category" — derived from the socket: AM5/AM4 = AMD, LGA = Intel.

Three markets, three different metrics

Not every market measures popularity the same way. The three regional schemas differ in one key column because each site exposes different data:

🇺🇸
Newegg (USD) — rating + review_count

Newegg shows star ratings and review counts. Both fields are available and meaningful.

🇯🇵
Kakaku (JPY) — review_count only (no rating)

Kakaku.com shows review counts but not simple star ratings. Review volume is used as the popularity proxy.

🇰🇷
Danawa (KRW) — store_count (no ratings at all)

Danawa is a price comparison site. It shows how many stores carry a product — more stores = more popular/established product.

🧠
Why different metrics matter for your AI instructions

When you ask an AI to "add a bestsellers chart to the Korea dashboard," you now know to say: "use store_count as the ranking metric, since Danawa doesn't have review ratings." Being precise about the data schema means the AI makes the right architectural choice the first time.

The deduplification trick

When you scrape multiple pages for the same brand, the same product can appear on both page 1 and page 2. The scraper prevents duplicates using a set — a special data structure that refuses duplicate entries, like a guest list that bounces people who are already inside.

CODE 
seen_names: set[str] = set()

# ... inside the product loop:
key = model.lower()
if key in seen_names:
    continue
seen_names.add(key)
PLAIN ENGLISH

Create an empty set called seen_names. It will track every product name we have already saved.

(Inside the loop, for each product we find:)

Convert the model name to lowercase — so "X870E NOVA WIFI" and "x870e nova wifi" count as the same product.

If this lowercase name is already in our seen_names set, it is a duplicate...

...skip it and move to the next product (the "continue" command jumps to the next loop iteration).

Otherwise, add this name to the set — it's now "registered" and won't be added again.
