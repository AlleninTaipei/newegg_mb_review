Meet the Pipeline Cast

Three roles, three regions, nine files, one shared toolkit that runs them all.

Picture a shipping dock with three loading bays, one bound for Newegg, one for Kakaku, one for Danawa. Module 1 showed you the diagram of all three bays working at once. This module walks the dock and puts a name and a job title on every crate in that diagram.

Same Three Job Titles, Every Port

Every bay stamps the same three job titles on its crates. Only the contents inside differ by port.

🔍
Scraper

Visits the marketplace site and copies every motherboard listing it finds into a raw JSON file.

📊
Dashboard Generator

Reads that JSON file and builds the ranked, human-readable dashboard.html report.

✉️
Email Sender

Takes the finished dashboard and delivers it straight to an inbox over SMTP.

💡
Key Insight

Three roles (Scraper, Generator, Sender) times three regions (Newegg, Kakaku, Danawa) is nine files. Add the shared orchestrator (run_all.sh) and the shared GitHub Actions workflow that schedules everything, and that's the entire cast. Nine files isn't nine things to learn, it's the same three things, times three.

Same Paperwork, Different Port

Every scraper file opens with a docstring, a plain-language note explaining what's inside the crate. Compare Newegg's label to Danawa's.

scraper.py

"""
Newegg Motherboard Scraper
Fetches ASRock, ASUS, Gigabyte, MSI motherboard listings and saves to motherboard_reviews.json
"""

danawa_scraper.py

"""
Danawa Motherboard Scraper
Fetches ASRock, ASUS, MSI, Gigabyte motherboard listings and saves to danawa_reviews.json

Output format mirrors motherboard_reviews.json (Newegg scraper) except:
  - price field is price_krw (Korean Won) instead of price_usd
  - rating/review_count replaced by store_count (number of stores carrying the product)
  - source is "Danawa"

Uses the AJAX endpoint that backs the Danawa listing page JS pagination.
"""

Danawa's label goes further. It spells out every way its cargo differs from Newegg's, right down to the endpoint the scraper quietly calls with AJAX instead of loading a plain page.

The Casting List

Not every difference between brands needs a whole separate file. Inside scraper.py, one small dictionary decides which brands get scraped and how far.

CODE 

BRANDS = {
    "ASRock":  {"n_val": 50001944, "max_pages": 3},
    "ASUS":    {"n_val": 50001315, "max_pages": 5},
    "MSI":     {"n_val": 50001312, "max_pages": 5},
    "Gigabyte":{"n_val": 50001314, "max_pages": 5},
}
PLAIN ENGLISH

This defines a dictionary named BRANDS. Every brand name is a key that points to its own settings, one small config block per brand.

ASRock maps to n_val 50001944, Newegg's internal ID number for that brand's filter, plus a cap of 3 pages to scrape.

ASUS, MSI, and Gigabyte each get their own n_val, but all three are allowed up to 5 pages, more than ASRock.

The closing brace ends the table. Four brands, four settings, one place to look.

Naming the Cast Pays Off

Once you can say Scraper, Generator, or Sender out loud, you can steer AI with precision: "add a min_reviews filter to the generator, not the scraper." Vague instructions let AI guess, and guesses sometimes land in the wrong file.
