The Clever Tricks

A handful of small, reusable ideas do most of the heavy lifting in this codebase, from spotting a chipset buried in messy text to catching a price change overnight.

A product title that hides everything

ASRock X870E Nova WiFi 5G AM5 ATX Motherboard

No box on that listing says "chipset: X870E" in a clean, labeled field. Every time the code sees a title like this, for every brand and every language, it has to figure out the socket, the chipset, and the form factor entirely on its own.

Playing birdwatcher with a blurry photo

A birdwatcher spotting a rare species through the trees doesn't wait for the bird to introduce itself. One distinctive marking, a wing bar, an eye ring, is enough to name the species with confidence.

parse_chipset works the same way: instead of asking the page for a clean field, it scans the messy title for one distinctive marking, an exact chunk of text like "X870E", and the moment it spots one, the identification is done.

CODE 

def parse_chipset(name: str) -> str:
    u = name.upper()
    # Ordered: more specific first
    for cs in [
        "X870E", "X870", "X670E", "X670", "X570", "X470", "X370",
        "B850",  "B650E","B650",  "B550", "B450", "B350", "A520",
        "Z890",  "Z790", "Z690",  "Z590", "Z490", "Z390", "Z370", "Z270", "Z170",
        "W790",  "W680",
        "B860",  "B760", "B660",  "B560", "B460", "B365", "B360", "B250",
        "H810",  "H770", "H670",  "H570", "H470", "H410", "H370", "H310",
        "H270",  "H170", "H110",
        "N100",  "N305", "N97",   "J6412",
        "X299",  "X399", "TRX40", "TRX50",
    ]:
        if cs in u:
            return cs
    return "Unknown"
PLAIN ENGLISH

First, make the whole title uppercase, so "x870e" and "X870E" both match the same way.

Then walk down a long list of every known chipset code, but in a very deliberate order, most specific first.

The moment one of these exact chunks of text, a substring, turns up anywhere inside the title, that is the answer.

If nothing on the whole list ever turns up, admit it: the chipset is "Unknown".

Notice there's no regex here, no clever pattern language. Just a plain "is this text inside that text" check, repeated down a carefully ordered list.

Look at that list again: "X870E" sits right before "X870". That's not an accident, it's the whole trick.

💡
Greedy Matching Order

Checking longer, more specific strings before shorter, more general ones is a pattern engineers call greedy matching order. Get the order wrong, put "X870" before "X870E", and every X870E board silently gets misidentified as a plain X870, with no error and no warning, just a quietly wrong answer.

Five tricks doing most of the work

Once you can name these five patterns, you'll spot them everywhere else too.

Ordered Substring Matching

Like a birdwatcher spotting one marking in a blurry photo, the code scans messy titles for exact chipset text, most specific names checked first.

🗂️

Dedup by Normalized Key

Before counting a product, its name is lowercased and checked against every name already seen. Spotted on two different pages? It's only counted once.

Distributor-Suffix Stripping

Korean listings often tack a distributor's name onto the end of a product name. This code chops it off, word by word, before anything else happens.

📸

Yesterday-vs-Today Diffing

Like a spot-the-difference puzzle between two photos, the code keeps yesterday's data and compares it to today's, product by product, to catch every price change.

def strip_distributor(name: str) -> str:
    """Remove trailing Korean distributor/importer name from product name."""
    parts = name.split()
    while parts and parts[-1] in DISTRIBUTORS:
        parts.pop()
    return " ".join(parts)

Spot the difference, but for prices

Remember those kids' puzzles with two nearly-identical photos side by side, and you had to circle everything that changed between them? That's exactly the game the code plays with yesterday's prices and today's.

But to play that game, it first needs to keep yesterday's photo instead of throwing it away the moment today's arrives.

CODE 

    if os.path.exists(OUTPUT_FILE):

Right before overwriting the results, the old file is copied to a "pre" file first. That copy is a snapshot, a frozen photo of yesterday, kept around just long enough to compare against.

CODE 

def compute_price_diff() -> list:
    """Return list of (name, old_price, new_price, diff) for changed/new products."""
    if not PRE_FILE.exists() or not DATA_FILE.exists():
        return []
    with open(DATA_FILE, encoding="utf-8") as fh:
        cur = json.load(fh)
    with open(PRE_FILE, encoding="utf-8") as fh:
        pre = json.load(fh)

    def flatten(data):
        result = {}
        for brand_obj in data.get("brands", {}).values():
            for item in brand_obj.get("products", []):
                result[item["name"]] = item
        return result

    cur_map = flatten(cur)
    pre_map = flatten(pre)
    diffs = []
    for name, ni in cur_map.items():
        np = ni.get("price_usd")
        if np is None:
            continue
        oi = pre_map.get(name)
        if oi is None:
            diffs.append((name, None, np, None))
        elif oi.get("price_usd") != np:
            diffs.append((name, oi["price_usd"], np, np - oi["price_usd"]))
    return diffs
PLAIN ENGLISH

First, check both files actually exist. If either the old snapshot or the new one is missing, there's nothing to compare, so give up with an empty list.

Open today's data and yesterday's data, both saved as JSON, a plain-text way of storing structured data.

flatten() digs every product out of its brand grouping and builds one big lookup table, keyed by the product's name, so any product can be found instantly instead of searched for.

Build two of these lookup tables: one from today's data, one from yesterday's.

For every product in today's list, skip anything that doesn't have a listed price.

Look that same product name up in yesterday's table. Never seen before? It's new. Price changed? Record the old price, the new price, and the diff between them.

Same tricks, every project

None of these five patterns are special to motherboards or chipsets. They show up in nearly every AI-assisted data project you'll ever ask someone, or something, to build.

Next time you're describing a task to an AI assistant, you now have the words for it: "strip the noise before deduplicating," "diff this against yesterday's snapshot," "ship it as a self-contained HTML file." Naming the pattern is half of asking for it correctly.
