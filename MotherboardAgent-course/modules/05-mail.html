The Mail Room

Environment variables, SMTP, MIME — and how a Python script sends a polished email with a dashboard attached.

The secrets problem

To send an email, the script needs your Gmail address and password. But hardcoding a password directly in a Python file is a serious security risk — anyone who sees the code sees the password. The solution: environment variables.

Think of environment variables as a keychain that lives outside the codebase. The script borrows the key when it needs it, but the keychain itself is never left lying around in the code.

❌

Wrong: hardcoded secret

password = "mypassword123" — anyone who reads or shares the file now has your password.

✅

Right: environment variable

password = os.environ.get("EMAIL_PASSWORD") — the code reads the password from the system at runtime. The password lives only in .env, which is never committed to git.

The .env file: your local secrets locker

The .env file is a plain text file that lives in the project folder. It lists the environment variables you want available when you run the scripts. The python-dotenv library reads this file automatically when the script starts.

.env FILE 
EMAIL_SENDER=you@gmail.com
EMAIL_PASSWORD=abcd efgh ijkl mnop
EMAIL_RECIPIENT=boss@company.com,team@company.com
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
PLAIN ENGLISH

The Gmail address the email is sent FROM. This must be the account whose app password you are using.

A 16-character Gmail App Password — NOT your regular password. You create this in Google Account settings under Security. It looks like 4 groups of 4 letters.

Who receives the email. Multiple addresses are separated by commas — the script splits this string and sends to each one.

Gmail's outgoing mail server address. For Gmail this never changes.

Port 587 is the standard port for SMTP with STARTTLS encryption — secure email submission.

SMTP: the postal protocol

SMTP is the protocol for sending email — the set of rules that governs how email travels from your Python script to Gmail's servers and onward to the recipient.

Building a MIME message: the email sandwich

An email is not just text — it can contain multiple parts: plain text, styled HTML, and file attachments. The MIME standard defines how to package all these parts into one message that email clients can interpret correctly.

CODE 
msg = MIMEMultipart("mixed")
msg["From"]    = SENDER
msg["To"]      = ", ".join(recipients)
msg["Subject"] = subject

alt = MIMEMultipart("alternative")
alt.attach(MIMEText(build_text_body(summary), "plain", "utf-8"))
alt.attach(MIMEText(build_html_body(summary), "html",  "utf-8"))
msg.attach(alt)
PLAIN ENGLISH

Create the outer container for the whole email. "mixed" means it will hold both a body and file attachments.

Set the From header — who the email appears to come from.

Set the To header. If there are multiple recipients, join their addresses with commas.

Set the Subject line — includes the date tag like "[Newegg] Motherboard Dashboard [2026-04-15]".

Create an inner container for the email body. "alternative" means: here are two versions — plain text AND HTML. The email client picks whichever it supports.

Attach the plain-text version — a simple text summary for clients that don't render HTML.

Attach the HTML version — the styled email body with KPI cards, brand table, and picks.

Attach the inner body container to the outer message container.

Attaching the dashboard file

The HTML summary in the email body is designed for mobile — quick scanning on a phone. The full interactive dashboard is attached as a file, meant to be opened on a desktop browser where the filters and charts really shine.

CODE 
html_bytes = DASHBOARD_FILE.read_bytes()
attachment = MIMEApplication(html_bytes, Name="dashboard.html")
attachment["Content-Disposition"] = \
    'attachment; filename="dashboard.html"'
msg.attach(attachment)
PLAIN ENGLISH

Read the entire dashboard.html file as raw bytes (binary data — the computer's native format for files).

Wrap the bytes in a MIME attachment object. Give it the filename "dashboard.html" so email clients know what to call it.

Set the Content-Disposition header — this tells the email client "this is an attachment" (as opposed to inline content that should display in the email body).

The filename appears in the email's attachment tray — what the recipient sees and downloads.

Attach this file to the outer message. The email now has: body text, HTML body, and dashboard.html attached.

🔒
Why App Passwords, not your regular password

Gmail blocks "less secure" direct logins. An App Password is a 16-character code specific to this script. If it ever leaks, you revoke just that code without changing your main password. This is called least privilege — granting only the minimum access needed.
